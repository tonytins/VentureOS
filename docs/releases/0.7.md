# VentureOS 0.7, Seto

VentureOS 0.7 gets apps onto a running VentureOS and refines what's there: `vdb` sends an app from another computer,
every app runs as a supervised process, the dock and the menu bar become apps, interfaces nest, apps' text comes from
string tables, and Roundhouse gains projects and a welcome window. The last build is 0.7.712, tagged `v0.7.712`. The
[changelog](../../changelog.md) lists each build's changes, from 0.7.104 to 0.7.712.

## Before you start

- VentureOS still runs from memory, under QEMU on x64. It builds for ARM64 too, but hasn't been booted there.
- Nothing outlasts a restart, including developer mode, trusted computers, and apps sent with `vdb`.
- 0.7 is the only supported release. Until 1.0, only the latest release is.

## Send an app with vdb

- `vdb`, in [`tools/vdb`](../../tools/vdb/README.md), sends an app from Linux, macOS, or Windows to a running VentureOS:
  `vdb install Dice.app --launch` installs and opens it, and `--for 5` or `--follow` prints what it prints. It never
  asks anything, and exits with 1 and VentureOS's reason when something's refused.
- Settings ▸ Developer turns on developer mode, and VentureOS listens on port 28455 while the desktop runs. A computer
  it doesn't know is asked about first, with Trust and Deny. `./run.sh --vdb` forwards the port into QEMU.
- An app sent is checked as apps are at boot, installed in `/mnt/user/apps`, and opened, replacing an open copy.
- Connections are encrypted with ChaCha20-Poly1305, with keys made from your computer's identity, which crosses the
  network once, when you choose Trust. `vdb identity --lua` prints the lines for a git-ignored `developer.local.lua`
  that turns developer mode on and trusts your computer at boot, so it never crosses at all.

## Apps as processes

- Every app is a process with an ID. `ps` lists them, and `kill` ends one by its ID, name, or identifier.
- An app whose code fails three times within a minute is closed, and the desktop says it crashed, in front of the
  errors that led to it.
- Files and Dock are kept running: closed or crashed, they're back at once.

## The desktop

- The dock is an app, Dock, drawn as a panel, so zoomed and new windows stop above it. Settings ▸ Dock offers Always
  visible, Hide automatically, and Hide when a window covers it.
- The menu bar is Files' top panel, and works as before, submenus now included: rest the pointer on one, or use the
  right arrow, Enter, or its letter.
- The desktop opens without a Files window; its dock icon or New Window opens one.
- New defaults: the Charger wallpaper, Auto style, and a time zone of UTC−5. Settings gives wallpapers a section of
  their own, and Files has a Home bookmark for `/mnt/user`.
- Notes has Note ▸ Sort By: Order Added, Newest First, and A to Z.

## Roundhouse

- **Projects** (`.rproj`) hold an app and its interfaces while you work on them. Roundhouse makes the `.app` only to
  run it, and File ▸ Export… writes it where you choose. Opening a stray `.app` offers to make a project from it.
- **A welcome window** opens when you start with nothing named: New Interface…, New App…, New Project…, Open…, and
  your recent items. File ▸ Close brings it back.
- **New Interface** (Ctrl+Alt+N) opens a blank canvas at once; the first Save asks where it goes.
- **Run** is a drop-down: Run in Simulation (Ctrl+R), and Run on VentureOS (Ctrl+Alt+R), which sends the app, unsaved
  edits included, to a VentureOS running under `./run.sh --vdb` and shows what it prints.
- **The outline is a tree.** Menus and panes fold, and Edit ▸ Move Into and Move Out (Tab and Shift+Tab in the
  outline) put the selection in the menu or pane before it, or take it back out.
- **String tables** (`.cst`) are highlighted, and checked as VentureOS reads them as you type; the designer shows a
  table's unsaved edits.

## For app writers

- The UIScript spec now lives in VentureOS, in [`docs/uiscript/`](../uiscript/README.md), and Hudini reads a subset
  of it. Menus, sidebars, shelves, panes, and panels are ordinary elements, and `requires` is no longer needed.
- A `<Menu>` can hold its items, separators, and submenus, and a `<Pane>` its controls, rather than each naming its
  parent. Both forms work.
- `<Panel width="…" height="…" edge="top|bottom">` opens a panel pinned to an edge, and a `<Shelf>` shows a row of
  icons, filled with `window:setItems`.
- A `<Sidebar>` of `<Pane>`s switches panes with no Lua.
- String tables are read to the full CST specification, by CST.NET. Tables numbered 100 and up are VentureOS's shared
  ones, in `/mnt/system/strings`; table 100 holds OK, Cancel, Save, and the like. References between tables work, one
  step deep.
- Lua gains `venture.cst.get`, `venture.cst.format`, and `window:string` for text; `venture.processes()` and
  `venture.kill(target)`; `venture.desktop`, for what the dock does; `venture.developer`; and `dock` in
  `venture.appearance()`.

## Breaking changes

- vdb tools and VentureOS builds from before 0.7.406 can't talk to these. Rebuild the tool with `swift build` in
  `tools/vdb`.
- `<Window role="panel">` is read as an ordinary window; a panel is `<Panel>` now.
- An app's own string table numbered 100 or more is reported and skipped.

## Known limits

- Twenty library tests still expect the defaults and layouts from before 0.7.709, such as the Earthset wallpaper,
  Light style, and Settings' old pane order. VentureOS itself is unaffected; the tests fail because they pin what the
  shipped apps look like, not because the apps are wrong.
- Roundhouse runs on your computer, not on VentureOS. A version for VentureOS itself waits on the platform: hosting
  one interface inside another, pointer input in regions, styled text, and persistence.
- Run in Simulation has no kernel underneath, so drivers, networking, and the shell's built-in commands aren't there.
